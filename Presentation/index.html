What the assignment asked us to do

We were given the UC Berkeley Pac-Man code (search.zip). We could only edit two files. An autograder checks every question.

The rules

  • Group of 4. Everyone must understand all of the code, not only their own part.
  • Edit only search.py (Q1–Q4) and searchAgents.py (Q5–Q7).
  • Use util.Stack, util.Queue and util.PriorityQueue, not Python built-ins.
  • Use graph search: never expand the same state twice.
  • Never rename files, functions or classes. The autograder finds them by name.
  • Heuristics must be admissible and consistent. A wrong one scores 0.

Part 4 · How the parts fit

Each part builds on the one before

The order matters: later questions call the code from earlier ones. This is the order the work came together.

  1. Setup + skeletonMember 1 writes the graph-search loop with DFS and BFS.
  2. CostsMember 2 swaps in a priority queue: UCS.
  3. GuessesMember 2 adds a heuristic to the priority: A*.
  4. CornersMember 3's problem runs on BFS (Q5) and A* (Q6).
  5. All dotsMember 4's heuristic runs on A* and uses BFS for maze distance.
  6. Ship itMember 4 merges, runs the full autograder, builds report + zip.

Same loop, different fringe

Every algorithm runs the same 4 steps: put the start on the fringe; take one out; if it is the goal, return its path; otherwise mark it expanded and add its neighbours. The only change is which node comes out next.

DFSutil.StackLast in, first out. Dives deep.
BFSutil.QueueFirst in, first out. Ring by ring.
UCSPriorityQueue(g)Cheapest cost so far first.
A*PriorityQueue(g + h)Cost so far + guess of cost left.

Q1

Depth First Search

Member 1search.py4 marks

Asked: find a path to the food dot using DFS, as graph search.

Our idea

  • Keep a stack of (place, path to get there).
  • Always take the newest one, so Pac-Man dives down one corridor first.
  • Keep an expanded set so we never open the same place twice.
  • If the stack runs out, return an empty list (no path).
search.py · depthFirstSearchfringe = util.Stack()
fringe.push((problem.getStartState(), []))
expanded = set()
while not fringe.isEmpty():
    state, path = fringe.pop()
    if problem.isGoalState(state):
        return path
    if state not in expanded:
        expanded.add(state)
        for successor, action, _ in problem.getSuccessors(state):
            if successor not in expanded:
                fringe.push((successor, path + [action]))
return []

Why it works: the expanded set stops loops, so DFS always ends. It finds a path, but not always the shortest. Here it is 130 steps long, while BFS finds 68.

Q2

Breadth First Search

Member 1search.py4 marks

Asked: the same, but with BFS. Only the fringe should change.

Our idea

  • Copy the DFS loop and swap the stack for a queue.
  • The oldest entry comes out first, so the search spreads out in rings.
  • The first time the goal comes out, it was reached in the fewest steps.
search.py · breadthFirstSearchfringe = util.Queue()          # the only line that differs from DFS
fringe.push((problem.getStartState(), []))
expanded = set()
while not fringe.isEmpty():
    state, path = fringe.pop()
    if problem.isGoalState(state):
        return path
    if state not in expanded:
        expanded.add(state)
        for successor, action, _ in problem.getSuccessors(state):
            if successor not in expanded:
                fringe.push((successor, path + [action]))
return []

Why it works: every step costs 1, so “fewest steps” means “cheapest”. BFS is optimal here. It looks at more places (269) but finds the shortest path (68).

Q3

Uniform Cost Search

Member 2search.py4 marks

Asked: find the cheapest path when steps can cost different amounts.

Our idea

  • Use a priority queue. The priority is the total cost so far, g(n).
  • Each entry also stores its cost, so the next step adds to it.
  • Test for the goal when a node is taken out, not when it is put in.
search.py · uniformCostSearchfringe = util.PriorityQueue()
fringe.push((problem.getStartState(), [], 0), 0)
expanded = set()
while not fringe.isEmpty():
    state, path, cost = fringe.pop()
    if problem.isGoalState(state):
        return path
    if state not in expanded:
        expanded.add(state)
        for successor, action, stepCost in problem.getSuccessors(state):
            if successor not in expanded:
                newCost = cost + stepCost
                fringe.push((successor, path + [action], newCost), newCost)
return []

Why it works: the cheapest path always comes out first, so when the goal comes out nothing cheaper is left. In the replay, the east side is cheap (cost 0.5x), so Pac-Man hugs the right.

Q4

A* Search

Member 2search.py4 marks

Asked: UCS plus a heuristic h, an estimate of the cost still to go.

Our idea

  • Same as UCS, but the priority is f = g + h.
  • g = cost so far. h = guess of cost left.
  • Places that are heading the right way come out first.
  • With nullHeuristic (h = 0) it is exactly UCS.
search.py · aStarSearchstart = problem.getStartState()
fringe = util.PriorityQueue()
fringe.push((start, [], 0), heuristic(start, problem))
expanded = set()
while not fringe.isEmpty():
    state, path, cost = fringe.pop()
    if problem.isGoalState(state):
        return path
    if state not in expanded:
        expanded.add(state)
        for successor, action, stepCost in problem.getSuccessors(state):
            if successor not in expanded:
                newCost = cost + stepCost
                fringe.push((successor, path + [action], newCost),
                            newCost + heuristic(successor, problem))
return []

Why it works: if h never guesses too high (admissible) and never drops by more than one step's cost (consistent), A* is still optimal. It just skips useless places: 549 nodes vs 620 for UCS, same 210-step path.

Q5

Finding All the Corners

Member 3searchAgents.py8 marks

Asked: design a search problem whose goal is to touch all four corners. Keep the state small and hashable.

Our idea

  • State = (position, visited). visited is 4 True/False flags, one per corner.
  • Goal: all 4 flags are True.
  • For each move that does not hit a wall, step there and tick the corner if we landed on one.
  • No walls or game state inside the state, so it stays tiny.
searchAgents.py · CornersProblemdef getStartState(self):
    visited = tuple(self.startingPosition == c for c in self.corners)
    return (self.startingPosition, visited)

def isGoalState(self, state):
    return all(state[1])

# inside getSuccessors, for each action:
(x, y), visited = state
dx, dy = Actions.directionToVector(action)
nextx, nexty = int(x + dx), int(y + dy)
if not self.walls[nextx][nexty]:
    nextPos = (nextx, nexty)
    newVisited = tuple(v or nextPos == c
                       for v, c in zip(visited, self.corners))
    successors.append(((nextPos, newVisited), action, 1))

Why it works: the same square counts as a new state once a new corner is ticked, so Pac-Man may walk back the way he came. BFS then finds the shortest tour, 106 steps.

Q6

Corners Heuristic

Member 3searchAgents.py8 marks

Asked: a heuristic for Q5 that is admissible and consistent. Full marks at ≤1200 nodes.

Our idea

  • Pretend there are no walls. That is a “relaxed” (easier) problem.
  • Try every order of visiting the corners still left (at most 4! = 24).
  • Return the shortest tour, using Manhattan distance.
  • Return 0 when all corners are visited.
searchAgents.py · cornersHeuristicposition, visited = state
remaining = [c for c, v in zip(corners, visited) if not v]
if not remaining:
    return 0

def manhattan(a, b):
    return abs(a[0] - b[0]) + abs(a[1] - b[1])

def cheapestTour(current, todo):
    if not todo:
        return 0
    return min(manhattan(current, c) + cheapestTour(c, [r for r in todo if r != c])
               for c in todo)

return cheapestTour(position, remaining)

Why it works: walls only make paths longer, so the no-wall tour is never more than the real cost (admissible). One real step changes the tour by at most 1 (consistent). The result is 741 nodes, down from 1966.

Q7

Eating All the Dots

Member 4searchAgents.py8 marks

Asked: a heuristic for eating every dot. Admissible and consistent. Full marks at ≤9000 nodes on trickySearch.

Our idea

  • Find the dot that is farthest from Pac-Man.
  • Use the real maze distance (walls included), from the given BFS helper mazeDistance.
  • Save each distance in problem.heuristicInfo, so each BFS runs only once.
  • Return 0 when no food is left.
searchAgents.py · foodHeuristicposition, foodGrid = state
food = foodGrid.asList()
if not food:
    return 0
cache = problem.heuristicInfo.setdefault('distCache', {})

def dist(a, b):
    key = (a, b)
    if key not in cache:
        cache[key] = mazeDistance(a, b, problem.startingGameState)
    return cache[key]

return max(dist(position, f) for f in food)

Why it works: to eat every dot, Pac-Man must at least walk to the farthest one, so the guess is never too high (admissible). One step changes any maze distance by at most 1, so h(n) <= 1 + h(n') (consistent).
